# Code of Conduct

## 1. Our Commitment

We are committed to maintaining a respectful, inclusive, professional, and collaborative environment for everyone involved in this project.

All team members, contributors, reviewers, and users are expected to communicate respectfully and contribute constructively to the development and improvement of the project.

We aim to ensure that everyone can participate without harassment, discrimination, intimidation, or inappropriate behaviour.

---

## 2. Expected Behaviour

All participants are expected to:

- Treat other contributors with respect and professionalism.
- Communicate clearly, politely, and constructively.
- Respect different opinions, ideas, and technical approaches.
- Provide constructive feedback during code reviews and discussions.
- Work collaboratively to solve technical and project-related problems.
- Respect the contributions and work of other team members.
- Follow the project's technical, academic, and security requirements.
- Use GitHub issues, pull requests, discussions, and other communication channels responsibly.
- Keep project-related discussions focused and professional.

---

## 3. Unacceptable Behaviour

The following behaviours are considered unacceptable:

- Harassment, discrimination, intimidation, or bullying.
- Personal attacks, insults, or threats.
- Offensive, abusive, or inappropriate language directed at others.
- Deliberately disrupting another contributor's work.
- Publishing another person's private or confidential information without permission.
- Deliberately introducing malicious code or security vulnerabilities.
- Misrepresenting or claiming another contributor's work as one's own.
- Abusing GitHub issues, pull requests, discussions, or other project resources.
- Any behaviour that creates a hostile, unsafe, or unprofessional environment.

---

## 4. Code and Security Responsibilities

Contributors are responsible for ensuring that their contributions do not intentionally compromise the security or reliability of the project.

Contributors should:

- Review code before submitting pull requests.
- Avoid introducing known security vulnerabilities.
- Follow appropriate coding and security practices.
- Report security issues responsibly.
- Avoid committing passwords, API keys, access tokens, private keys, or other sensitive credentials.
- Remove sensitive information if it is accidentally committed and report the incident to the project maintainer.
- Avoid intentionally exploiting vulnerabilities in project systems or infrastructure.

Security-related issues should be handled responsibly and should not be used to harm the project, its contributors, or its users.

---

## 5. Academic and Project Integrity

As this project is developed as part of an academic and collaborative environment, contributors are expected to maintain academic and professional integrity.

Contributors should:

- Submit their own work or clearly acknowledge contributions from others.
- Properly reference external sources where required.
- Avoid plagiarism or misrepresentation of work.
- Clearly identify significant contributions made by other team members.
- Follow the academic requirements and policies applicable to the project.

---

## 6. Collaboration and Code Review

Contributors should use pull requests and code reviews to improve the quality and reliability of the project.

When reviewing code, contributors should:

- Focus on the code and proposed changes rather than the individual.
- Provide constructive and specific feedback.
- Explain technical concerns clearly.
- Respect reasonable differences in implementation approaches.
- Avoid unnecessary or disrespectful criticism.
- Respond to feedback professionally.

Disagreements should be resolved through respectful technical discussion and, where necessary, consultation with the project maintainer.

---

## 7. Reporting Issues

If you experience or observe behaviour that violates this Code of Conduct, you should report the issue to the project maintainer or an appropriate project team member.

Reports should include relevant information where possible, such as:

- A description of the incident.
- The date or approximate time of the incident.
- Relevant GitHub issues, pull requests, messages, or commits.
- Any other information that may help understand the situation.

Reports will be reviewed fairly and handled as confidentially as reasonably possible.

---

## 8. Handling Reports

Project maintainers will review reported incidents and determine an appropriate response based on the circumstances.

The response may include:

- Requesting clarification or additional information.
- Providing a private warning.
- Removing inappropriate content.
- Restricting participation in project discussions.
- Restricting or removing repository access.
- Removing a contributor from the project.
- Reporting serious incidents to an appropriate authority where necessary.

Actions will be proportionate to the seriousness and circumstances of the violation.

---

## 9. Enforcement

Project maintainers are responsible for interpreting and enforcing this Code of Conduct.

Maintainers are expected to handle reports fairly and consistently while avoiding unnecessary disclosure of personal or confidential information.

Retaliation against anyone who reports a concern in good faith is not acceptable.

---

## 10. Scope

This Code of Conduct applies to all project-related activities, including but not limited to:

- Source code contributions.
- Git commits and branches.
- Pull requests.
- Code reviews.
- GitHub issues.
- GitHub discussions.
- Project documentation.
- Team meetings.
- Project-related communication.
- Other activities directly associated with the project.

This Code of Conduct applies whether the activity takes place within the GitHub repository or through other project-related communication channels.

---

## 11. Contributor Responsibilities

Everyone participating in the project shares responsibility for maintaining a respectful, secure, and collaborative environment.

Contributors should:

- Follow this Code of Conduct.
- Respect other team members.
- Raise concerns appropriately.
- Protect project and user information.
- Follow agreed development practices.
- Help maintain the quality, security, and reliability of the project.

---

## 12. Questions and Contact

Questions or concerns regarding this Code of Conduct should be directed to the project maintainer through the communication channels provided by the project.

For security vulnerabilities, contributors should use the project's designated security reporting process where available rather than publicly disclosing sensitive technical details.

---

## 13. Acknowledgement

By contributing to or participating in this project, individuals agree to follow this Code of Conduct and help maintain a respectful, professional, secure, and collaborative environment.

The project team may update this Code of Conduct when necessary to reflect changes in project requirements, collaboration practices, or applicable policies.
